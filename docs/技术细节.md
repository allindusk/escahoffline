## 1. 它是什么形态的程序

不是 Windows 桌面应用，也不是 Electron 壳，而是一个**本地 HTTP 服务 + 浏览器页面**：

```
启动.bat  →  python -m server --host 0.0.0.0 --open  →  8000
                     ├─ web/*.html      浏览器界面
                     └─ /api/*          下载 / 解包 / 导出 / 更新
```

端口默认 8000，被占用会自动往后找（8001、8002…），启动日志里会打印实际地址。
监听地址默认值看运行方式：**便携包 `0.0.0.0`**（同 Wi-Fi 的手机能扫码访问），
**源码方式 `127.0.0.1`**（仅本机，要给手机看得自己加 `--host 0.0.0.0`）。

技术栈刻意保持极简：**Python + 原生 JS**。前端没有构建步骤、没有 npm、没有框架；
后端除解包和图像处理必需的几个库之外，尽量只用标准库（多线程下载、HTTP、
文件与任务管理都是自己写的）。

理由：

- 便携工具要「解压即用」，任何前端构建链都会变成用户的负担
- 渲染交给浏览器，出问题能直接用 DevTools 看
- 便携包约 114 MB（其中大部分是内置的 Python 与依赖），跨平台
- 套一层 Electron 桌面壳只会增加分发成本和杀软误报

## 2. 依赖

| 方式 | 需要装什么 |
|---|---|
| Release 便携包 | 什么都不用装（内置 Python 便携版 + 依赖 + Real-CUGAN 超分引擎） |
| 源码运行 | `pip install -r requirements.txt` |

源码方式下 `requirements.txt` 里各依赖的用途：

| 包 | 作用 | 可以没有吗 |
|---|---|---|
| UnityPy、lz4 | 解官方 **Unity AssetBundle**（Sprite / AudioClip / TextAsset） | 不行，装剧情全靠它 |
| numpy | 算立绘表情差分的落点（全位移 SSD 匹配） | 不行，立绘会合不出来 |
| Pillow | 裁切、合成、写 WebP | 不行 |
| cryptography | 解官方清单的 AES-256-CBC | 可以，但解密会从几十毫秒变成 30–60 秒 |
| playwright、av | 导出 mp4（headless Edge 逐句截帧 + 编码） | 可以，只是「导出视频」不可用 |
| qrcode | 局域网二维码 | 可以（`server/_vendor` 里已内置一份） |

**超分**不靠 pip 包：需要 `realcugan-ncnn-vulkan` 引擎放在 `tools/realcugan/`，
便携包自带；没有引擎就不做超分，不会拿 Lanczos 插值糊弄（那只是像素变多、细节没增加）。

嫌 pip 慢可以直接双击 `启动.bat`：它检测到缺依赖会调用 `tools/bootstrap_deps.py`，
**先实测清华 / 阿里 / 腾讯 / 华为 / 中科大等镜像的下载速度，选最快的再下**
（实测同一时刻 PyPI 官方 288 KB/s，华为云 11.9 MB/s）。
只想看测速结果：`python tools/bootstrap_deps.py --test`。

## 3. 两个启动脚本

| 脚本 | 用途 | 端口 |
|---|---|---|
| 根目录 `启动.bat` / `start.sh` | 正常使用：`python -m server --host 0.0.0.0 --open` | 8000（占用自动往后找） |
| `web/dev-preview.bat` | 开发用：同样起完整后端，但走 `serve.py` 并**禁用浏览器缓存**，改完 HTML/CSS 刷新即见 | 8100 |

两者后端能力一致（安装剧情、检查更新、导出都能用），区别只在端口和缓存策略。
发布包里只有根目录那个，`web/` 下的是调试工具，不会打进去。
对应的停止脚本是 `web/dev-stop.bat`。

## 4. 安装一部剧情时到底发生了什么

没有「预处理好的资源包」这种东西，全部在本机现做：

| 步骤 | 说明 |
|---|---|
| ① 资源清单 | 拉官方 `Manifest1Ex` / `Manifest2Ex`（AES-256-CBC 加密，25,204 个 bundle 的 size / hash / 依赖图）。**清单不随程序附带**——它随官方更新变化，附带只会给你过期数据；首次提示下载（约 5 MB，有进度），官方上新后在「更新」页点「更新剧情目录」 |
| ② 算依赖 | 按命名规则反查这部剧需要哪些 bundle：剧本 1 个 + 语音按段 + 背景/立绘/CG 按剧本实际引用 |
| ③ 并发下载 | 默认 32 连接。官方 CDN 单连接只有 60–100 KB/s，瓶颈是每条连接的吞吐与 TLS 握手，并发是唯一有效手段（实测 32 并发 ≈ 7.7 MB/s） |
| ④ 解包 | UnityPy 读出 Sprite / AudioClip / TextAsset → WebP / m4a / 剧本 JSON |
| ⑤ 立绘合成 | 游戏里的立绘是「底图（脸挖空）+ 表情差分层」，落点靠 numpy 做全位移 SSD 匹配算出，与官方显示一致 |
| ⑥ 应用 | 写出 `web/data/char_<id>.js` 与 `web/media/...`，刷新索引映射 |

所以「装一部剧情」= 下载 + 解包 + 合成，全程本地完成，不需要用户另外准备任何分发包。
素材来源、包命名规则、域名覆盖与发版流程见 [`资源包与发布.md`](资源包与发布.md)。

> 旧版本提供过「自己打 zip 资源包」的模式（`tools/build_packs.py` + `tools/make_pack_archives.py`），
> 改用官方 CDN 直连后已不是主路径，脚本保留但不再需要运行。

**素材为什么不进仓库**：24.7 GB + 版权。程序只带索引（目录树、图片映射、清单种子），
素材按需下载解包。下载地址在源码里加密存放（`web/data/packs.links.js`，RC4 + base64），
运行时才解密；官方域名若变更，用户可在「设置 → 下载源」自行覆盖，不用改代码、不用重新打包。

## 5. 网络与自更新

### 下载线路

GitHub Release 的下载在部分网络下很慢（实测直连 `objects.githubusercontent.com` 只有
0.7 MB/s，还时不时握手失败）。程序自己取 GitHub 的东西（更新包、更新检查、角色信息）时，
固定按下面顺序试线路，**哪条有响应就用哪条、不测速**：

| 顺序 | 线路 |
|---|---|
| 1 | `https://gh-proxy.org/` + 原链接（主站，Cloudflare v4） |
| 2 | `https://v4.gh-proxy.org/` + 原链接（优选，仅 IPv4） |
| 3 | `https://v6.gh-proxy.org/` + 原链接（优选，IPv4/IPv6） |
| 4 | `https://cdn.gh-proxy.org/` + 原链接（Fastly v4） |
| 5 | GitHub 官方直连 —— 只在上面四条全都没响应时才用 |

手动下载也一样：把 Release 原链接整个粘在反代域名后面即可，例如
`https://gh-proxy.org/https://github.com/allindusk/escahoffline/releases/download/v1.0.5/ESCAH-Offline-v1.0.5-win64-portable.zip`。

### 更新机制

- **程序更新**：检查 GitHub Release → 下载到暂存区 → **退出后替换程序文件** → 自动重启。
  只覆盖 `server/`、`web/assets/` 等程序白名单，素材、译文、设置一个都不会丢。
  这套方案和 qBittorrent、PortableGit 的更新机制同理。
- **联网策略**：控制台「更新」页有「每次启动程序后检查更新」勾选框（默认勾选）。
  勾选时启动后**只查一次**，发现新版只在页面顶部挂一条提示，**不自动下载、不自动重启**；
  不想要联网就取消勾选。任何时候也可以手动点「检查程序更新」→「下载并应用」。

## 6. 目录结构

```
escahoffline/
├─ 启动.bat / start.sh     启动脚本（等价于 python -m server --host 0.0.0.0 --open）
├─ server/                 本地服务端（下载/解包/超分/导出/更新 API）
├─ web/                    站点（播放器 / CG 画廊 / 控制台）
│   ├─ data/               索引（进 Git）+ 剧情正文（资源包分发，不进 Git）
│   └─ media/              素材（永不进 Git）
├─ tools/                  维护脚本：build_packs / build_imgmaps / make_pack_archives / encrypt_links
├─ docs/                   文档
└─ userdata/               你的数据：config / state / 下载缓存 / 备份 / 导出 / 日志
```

更细的模块职责、数据链路、硬性约定与已知坑，见 [`AI-ONBOARDING.md`](AI-ONBOARDING.md)。

## 7. 二次开发

项目是**为 AI 协作而整理过的**：模块边界清楚、注释写「为什么」、有一份专门的接手文档。

- **接手文档：[`AI-ONBOARDING.md`](AI-ONBOARDING.md)**
  把这份文件（或仓库链接）发给 CodeBuddy / Cursor / Claude / Copilot 等任意 AI 编程助手，
  它就知道数据流、硬性约定、常见改法、验证清单和已知毒点。
- 一句可直接用的话：

  > 读 `docs/AI-ONBOARDING.md`，然后帮我 <你的需求>。改完按文档第 4 节的验证清单自测。

- 最值得投入的方向是**翻译**：[`翻译指南.md`](翻译指南.md) 写了完整流水线
  （导出 → AI 翻译 → 术语统一 → 导入 → 校验）。
- 剧情数据的结构与全部 Method 语义：[`数据格式.md`](数据格式.md)（改解析或演出逻辑时看这份）。
