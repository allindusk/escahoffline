# 翻译指南（用 AI 把剧情变成中文）

> 这是本项目**投入产出最高**的玩法。播放器已经把工程问题解决了（导出、对照、
> 合并、术语、校验），剩下的只有"翻得好不好"。

---

## 1. 为什么用 txt，而不是直接改 JSON

对话文本是**以日文原文为 key** 存的（`{"「おはよう」": "「早上好」"}`）。
直接编辑 JSON 有三个坑：容易漏逗号、编码容易坏、非程序员改起来痛苦。

所以中间层用一份**块式对照文本**——一句台词一个 `###` 块：

```
# ===== ESCAH 离线阅读器 · 剧情译文文件 =====
# 剧情标识 : char_1
# 剧情名称 : 神騎プラチネル
# 段落/句数: 6 段 / 695 句

### 001-p01-m003 【トキサダ】 (2行)
ja: 「おはよう」今日も
ja: 　いい天気ね
zh: 「早上好」今天
zh: 　天气也不错呢
```

块头 `### 编号 【说话人】 (行数)` 三段都有用：

| 部分 | 作用 |
|---|---|
| `001-p01-m003` | 剧情号 - 第几段 - 第几句。**稳定锚点**，AI 手滑改了原文也能落位 |
| `【トキサダ】` | 说话人（旁白时没有）。让 AI 定得下语气、自称和敬语 |
| `(2行)` | 原文行数。译文**不能超过**它（游戏文本框行数固定），少于则没关系 |

注意日文原文换行后顶格的是**全角空格** `　`，它是原文的一部分，别当多余空白删掉。

文件**末尾**还有一节发言人译名，管的是对话框上方显示的角色名：

```
# ===== 发言人译名（对话框上方那个名字）=====
### spk:トキサダ
zh: 
```

这张表是**全站共用**的（`web/assets/i18n/zh-Hans/_speakers.json`），不按剧情拆开——
同一个角色在几百部剧情里都叫 `トキサダ`，翻一次所有剧情都跟着变，不必逐部重翻。

为什么不能自动映射：剧情里的名字是**口语称呼**（トキサダ / ハルカ），而 `names.js`
存的是全长名（神騎プラチネル），实测按出现次数只有 2.3% 能对上。`男Ａ`/`強面の男たち`
这种路人名也在表里，翻成「男 A」「凶神恶煞的男人们」即可。留空就原样显示日文。



导入时服务端会解析并合并，告诉你有多少新增 / 更新 / 跳过 / 格式错误。

## 2. 完整流程

### 第一步：导出

播放器打开任意一部剧情 → 控制条「译文」→「⬇ 导出原文」→ 得到 `char_<id>.txt`。

也可以在「资源管理 → ⑤ 翻译」里对已安装的其他剧情批量处理（见第 5 节）。

### 第二步：交给 AI

把 txt **整个文件**发给 AI，附上下面的提示词（按需微调）：

```
你是日译中翻译，擅长日本 Galgame / 手游剧情的口语化翻译。

附件是《超昂大战》的剧情台词文件。格式：每句台词是一个以 ### 开头的块，
块内 ja: 是日文原文，zh: 是中文译文。

任务：给每个块补上 zh: 行，输出完整文件。规则：

1. 块头那一行（编号 / 【说话人】/ (N行)）原样保留，一个字都不要动。
2. ja: 行原样保留，一个字都不要动（标点、空格、全角空格「　」都算）。
3. zh: 写中文译文。原文几行就写几行 zh:，**绝不能超过 (N行)**；
   中文通常更短，能压成一行更好。
4. 【】里是说话人，没有就是旁白。按角色性格定语气、自称、敬语，同一角色前后一致。
5. 保留原有的「」『』（）用法；台词里的停顿、拉长音用中文习惯表达。
6. 拟声词（ドキドキ、ふわぁ…）译成中文拟声/状态描述，不要留日文假名。
7. 遇到露骨的性描写：只翻真正露骨的部分，拟声、惊叫、擦边、玩笑照常翻，
   不要因为"看起来敏感"就整段跳过。
8. 不想翻的块整块删掉（连带块头），不要留半截。
9. 文件末尾的 ### spk:名字 是角色名（对话框上方的发言人名），
   给 zh: 补中文译名即可；这是全站共用的表，不必逐部重翻。

以下是术语表，出现时必须按它翻：
<把你的术语表粘进来，或用 output/custom_dict.json 里的核心条目>
```

> 一次性给太多块会超出上下文。按块头里的 `p??`（第几段）分批，一次 1–2 段，
> 翻完再合并。

### 第三步：导回

播放器「译文」面板 →「选择译好的 txt…」→ 确认模式：

- **合并**（默认，推荐）：只写有 `zh:` 的块，已有译文保留
- **覆盖整部**：丢掉这部剧情原有译文重新写

点「✅ 导入并应用」→ 显示 `新增 X · 更新 Y · 跳过 Z · 格式错误 N` → 按 `F5` 刷新。

导入结果里还有两类**警告**，看到就要回头改：

- **译文行数超过原文**：会撑破对话框。会列出具体块编号，把译文压短。
- **原文对不上**：块的 `ja:` 行和剧本原文不一致（通常 AI 改了字，或块窜位了）。
  服务端已按编号落位救回，但仍建议核对那几块。

如果出现大量"格式错误"，一般是整份文件的块头被改坏了（比如 `###` 被换成 `1.`），
或者选的 txt 根本不是这部剧情。

## 3. 质量要点

### 术语统一

项目自带术语表 `output/custom_dict.json`（约 800 条日文 Galgame 常用词），
建议把其中与你剧情相关的条目贴进提示词。

**容易翻错的**（务必注意）：

| 日文 | 正确 | 错误 |
|---|---|---|
| ダメージを回復 | 恢复**所受伤害** | 恢复体力 |
| スタミナを回復 | 恢复**体力** | 恢复伤害 |
| 自身のダメージを完全回復 | 自身所受伤害完全恢复 | 自身完全恢复 |
| 継続回復（未指明对象） | 持续回复（保持中性） | 强行补成"持续回血" |

### 排版

不要逐字对着日文断行。**整句理解后按中文语境重新断行**，分段数不必与原文一致。

### 人名

角色名保持日文原名或统一用社区通用译名，**全篇一致**；同一角色不同称呼
（お兄ちゃん / 兄さん / あなた）要体现场合差异，不能一律"哥哥"。

### 露骨内容

按语义逐句判断：只有真正露骨才留空跳过，拟声、惊叫、习语、擦边都可以照常翻。
过度保守会让整段剧情读起来断裂。

## 4. 批量与进度

- 「资源管理 → ⑤ 翻译」看当前翻译库总量（多少部 / 多少句）
- 每部剧情导出一次，翻完导入，互不影响
- 译文文件可直接分享给别人（只有文本，不含素材，风险低于素材）——
  但仍建议只在可信范围内交换

## 5. 给做二开的人

译文层的实现只有两个函数，读一遍就能改：

- `server/exports.py::export_trans(unit)` → 生成对照 txt
- `server/exports.py::import_trans(unit, text, mode)` → 解析合并

相关约定：

- 译文仓库：`web/assets/i18n/zh-Hans/<unit>.json`，`{"messages": {"原文": "译文"}}`
- 索引：`web/assets/i18n/index.json`（各语言句数，用于显示覆盖率）
- 前端加载：`web/assets/js/i18n.js`（`loadStory(unit)`）
- 想加繁体/英文，把 `zh-Hans` 换成对应语言目录，并在 `i18n.js` 的 `supported` 里登记

如果你要做"AI 自动翻译流水线"（批量调 API），
建议复用 `import_trans()` 做落盘，别自己拼 JSON。
